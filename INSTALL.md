# Установка

Пакет `0.1.0-rc.1` предназначен для испытаний. Перед распространением как стабильного релиза требуются проверка новой установки, остановки, повторного подключения и перезагрузки на поддерживаемом устройстве.

## Подготовка

1. Сверьте маркировку **YNDX-00052** на корпусе. Установщик дополнительно проверит платформу, точный fingerprint прошивки `5000000921`, Android 9, API 28 и ARM64. Другие модели/прошивки не разрешаются параметром обхода.
2. ADB и root должны уже работать. Этот пакет их не устанавливает, не меняет SELinux, boot/recovery или `/odm`. Требуется не менее 256 MiB свободного места в `/data`.
3. На компьютере нужны Python 3.12+ и Android Platform Tools. Проверьте `adb version`, затем `adb devices`. Должна быть одна нужная станция в состоянии `device`; `unauthorized` нужно устранить вашим обычным способом подключения. Автоматического `adb connect` установщик не выполняет.
4. Скачайте установочный архив и `SHA256SUMS` из одного релиза. Проверьте скачанный файл:

```sh
# Linux
sha256sum -c SHA256SUMS --ignore-missing
# macOS: сравните результат с нужной строкой SHA256SUMS
shasum -a 256 ya-airplay-0.1.0-rc.1-install.tar.gz
```

Распакуйте архив и перейдите в созданную папку. Документы остаются на компьютере; на станцию попадут только рабочие компоненты.

## Проверка без установки

```sh
python3 tools/airplayctl.py check
```

Ожидается `compatible_properties: true` и доступное место. Эта команда только читает свойства; она не доказывает работу root, звука или пригодность другой аппаратной ревизии.

## Установка на Hybrid Root 1.2.4

```sh
python3 install.py --model YNDX-00052 --root rootd --hybrid-root-version 1.2.4 --voice on
```

Прочитайте подтверждение и введите `YES`. Если голосовая пауза не нужна, уберите `--voice on`. При нескольких подключённых устройствах добавьте к команде `--serial` с локальным идентификатором нужной станции.

Установщик сверяет состав и SHA-256 пакета, проверяет root и размещает новую установку в `/data/local/tmp/ya-airplay`. Вспомогательный root-запрос публикуется атомарно без перезаписи существующего запроса. При ошибке нет автоматического повтора или попытки другого root-метода.

NSD APK устанавливается только при отсутствии пакета `ya.station.airplay`. Если такой пакет уже есть, допускается только точное совпадение его SHA. При другой версии или подписи установка остановится: автоматического удаления APK нет.

В конце должны появиться подтверждённый статус supervisor `running` и сообщение об успешной установке. Выберите **YA Station Custom** на iPhone в той же сети. Начните с тихого трека. Проверьте регулировку громкости и несколько отключений/подключений.

При `--voice on` скажите «Алиса, пауза», проверьте состояние именно на iPhone, затем вручную нажмите Play и повторите. Между отдельными командами выдерживайте больше секунды. Голосовые Play/Next/Previous не заявлены поддерживаемыми. Мост зависит от фиксированного события штатного SDK; при его перезапуске мост безопасно завершится. Для повторного запуска отдельно от аудио доступна команда `voice-start` с теми же root-параметрами.

## Другой существующий root

Поддержаны прямой root ADB shell (`--root shell`) и `su 0 sh -c` (`--root su`). Они не предполагаются автоматически совместимыми с любым root manager: если выбранный способ не работает, установка остановится. Не запускайте обходные команды, меняющие системные разделы.

## Автозапуск

Для root manager, который **уже выполняет** скрипты из `/data/adb/service.d`, при первой установке можно добавить:

```sh
python3 install.py --model YNDX-00052 --root su --voice on --autostart required
```

Добавляется только собственный `/data/adb/service.d/ya-airplay.sh`. Чужой hook не заменяется. Скрипт ждёт завершения загрузки Android до 120 секунд и делает один запуск. Зацикленного перезапуска при ошибках нет. Файлы предыдущей загрузки сбрасываются только после подтверждённой смены boot ID; PID из старых файлов не используются для сигналов.

На испытанной конфигурации Hybrid Root 1.2.4 такой hook не найден. Поэтому её автозапуск остаётся **неподдержанным до отдельного решения и испытания**. Для ручного запуска после перезагрузки:

```sh
python3 tools/airplayctl.py start --root rootd --hybrid-root-version 1.2.4
```

## Управление и диагностика

Все команды запрашивают подтверждение; для rootd сохраняйте те же параметры доступа:

```sh
python3 tools/airplayctl.py status --root rootd --hybrid-root-version 1.2.4
python3 tools/airplayctl.py stop --root rootd --hybrid-root-version 1.2.4
python3 tools/airplayctl.py start --root rootd --hybrid-root-version 1.2.4
python3 tools/airplayctl.py pause --root rootd --hybrid-root-version 1.2.4
python3 tools/airplayctl.py play --root rootd --hybrid-root-version 1.2.4
```

`rtsp_ack` подтверждает ответ протокола, а не фактическое действие плеера. Оценивайте действие по iPhone.

## Обновление и прежняя экспериментальная установка

Повторная установка той же версии ничего не перезапускает и сверяет целостность. Для следующей публичной версии используется команда `update`; текущая установка целиком перемещается в `ya-airplay.previous`, пользовательская конфигурация сохраняется. Уже существующая резервная копия не перезаписывается.

Чужой или прежний экспериментальный AirPlay не захватывается автоматически. Если он работает, установка останавливается. Сначала нужен его отдельный штатный останов и сохранённый откат владельца. На исходной станции SF1/VP2 нельзя подменять этим пакетом без отдельного одобренного плана испытания.

## Что хранится на станции

Рабочая папка содержит бинарники, Volume Bridge, NSD APK, конфигурацию и скрипты. Документация, старые selftests и исходники на станцию не копируются. Каждый из четырёх журналов сеанса ограничен 8 MiB; сохраняются четыре прошлых сеанса и текущий (до 160 MiB суммарно). Удаляются только распознанные собственные журналы; неизвестные файлы/ссылки приводят к отказу очистки. Приватные журналы и резервные копии никогда не отправляются в GitHub автоматически.
